# Pusyuu メイキー (Meikee)

**データベースを使わない、PHP 1ファイル完結のアカウント基盤 + SSO プロバイダ。**

> **English summary**
> A single-file PHP account system and SSO provider that uses **no database at all**.
> Accounts live in an AES-256-GCM encrypted JSONL ledger; each user gets an isolated,
> encrypted, per-service key-value store ("p-drive"). No Composer, no framework,
> no RDBMS — one `index.php` and the PHP standard library. Runs without JavaScript.
> MIT licensed.

「メイキー(メイキィ)」は、このプロジェクトでの **アカウント** の呼び名です。

---

## これは何か

複数のWebサービスが1つのアカウントを共有するための、**ログイン基盤まるごと**です。
アカウントの作成・編集・削除・ログイン・ログアウト・パスワード再設定・リカバリコード・
フォロー/フォロワー・プロフィール画像、そして各サービスがユーザーごとのデータを
置くための暗号化ストレージまでが、**`p-meikiee/index.php` という1つのファイル**に
入っています。

依存パッケージはありません。Composer も、フレームワークも、**データベースも使いません**。

## なぜ公開するのか

これは実際に稼働していたシステムです。作者はこの先の構成を SQL へ移すことにしましたが、
**「RDBMSを使わずにここまで組める」という形そのものを捨てたくない**、というのが公開の
動機です。だから本リポジトリは「これから育てる新製品」ではなく、
**動く状態で保存された、一つの完成した設計** として読んでください。

そのぶん、コード中のコメントは異様に厚めです。「なぜこうなっているか」「これを変えると
何が静かに壊れるか」を、将来の編集者に向けて日本語で書き残してあります。仕様書ではなく
**コードそのものが一次資料** です。

## 設計上の要点

RDBMS を使わないぶん、整合性は「置き方」で担保しています。読みどころは以下です。

- **暗号化されたJSONL台帳** — アカウント本体は `base64(IV 12byte + TAG 16byte + 暗号文)`
  で1行ずつ暗号化。読み込み→変更→書き戻しは常に排他ロック下の1トランザクションです。
- **生IDをディレクトリ名にしない** — 各ユーザーのストレージは `sha256(生ID)` を名前に
  使います。ストレージは公開ディレクトリの内側にあるため、フォルダ名という
  "メタデータ" のレベルでも生IDを出さない、という方針です。
- **削除順序でフェイルセーフを作る** — アカウント削除は、付随データを**全部消せたと
  確認できるまで台帳に触れません**。失敗すれば「削除が無かったこと」になるだけで、
  「本体は消えたのに付随データが残る」中途半端な状態が構造的に発生しません。
  かつて逆順で実装していて実際に取り残しが出た、という経緯もコメントに残っています。
- **孤児データの掃除と監査ログ** — 台帳に存在しないストレージ、中断した分割
  アップロードの断片を検出して消します。**消す前に**「何があったか」を
  非公開ディレクトリの恒久ログへ必ず記録します。cron は使わず、通常のリクエストに
  便乗して1日1回だけ走ります。
- **使い切りコードによるSSO** — 他サービスはログインフォームを一切持ちません。
  メイキー本体の画面へ誘導し、成功したら60秒だけ有効な使い切りコードを付けて戻す。
  戻り先はそのコードをサーバ間通信で本物のトークンへ交換します。
- **JavaScript無しで完結** — 画面はすべてPHPが生成するHTMLとCSSだけで動きます。

## 動作要件

- PHP **8.0 以上**(`str_contains` を使用。8.1以降の機能は使っていません)
- 拡張: `openssl`(必須)、`mbstring`(必須)、`gd`(アバターの変換に必要)
- `intl` は任意(あれば国際化ドメインのメール検証が有効になります)
- Webサーバ: Apache / nginx いずれでも可
- **公開ディレクトリの外側に書き込めるディレクトリが1つ**(鍵とセッションの置き場)

データベース、Composer、Node は不要です。

## はじめかた

詳細は **[SETUP.md](SETUP.md)** にあります。最短では次の3つです。

1. `p-meikiee/` を公開ディレクトリへ置く
2. 暗号鍵を作る(**自動生成されません。必ずこの手順が要ります**)
   ```
   php tools/generate_key.php /path/to/.pusyuuHiddenFiles
   ```
   この置き場は **公開ディレクトリの外側** にしてください。
3. `p-meikiee/index.php` をブラウザで開き、`?account=create` からアカウントを作る

他サービスから使う場合は `client/meikiee_client.php` を読み込み、接続先を
`define()` で上書きします。手順は [docs/ACCOUNTS_INTEGRATION_SPEC.md](docs/ACCOUNTS_INTEGRATION_SPEC.md) を参照してください。

## リポジトリの構成

```
p-meikiee/
  index.php              本体。これ1つでサービスとして成立します
  assets/styles/         画面のCSS
  assets/posts/          アカウント台帳(account.jsonl)が作られる場所。中身は追跡しません
client/
  meikiee_client.php     他サービスがメイキーを呼ぶためのクライアント
docs/
  ACCOUNTS_INTEGRATION_SPEC.md   連携仕様(SSO・API・データモデル)
  P_DRIVE_INTEGRATION_SPEC.md    ユーザーごとストレージの仕様
tools/
  generate_key.php       初回セットアップ用の鍵生成
```

`p-meikiee/index.php` は、外部への `require` を2つ持っていますが**どちらも
`file_exists()` で囲まれた任意の連携** です。このフォルダだけ持ち出しても動きます。

## 含まれていないもの

- **管理パネル** — 稼働環境では別サービス(oppai)が担当していました。本体側に
  `?api=admin_*` の口だけが残っています。共有鍵を知るサーバからしか叩けません。
- **これを使っていた各サービス** — 掲示板・メモ・チャット等は含みません。
- **利用者のデータと暗号鍵** — 当然ながら含みません。`.gitignore` と
  [SETUP.md](SETUP.md) に、何が「ソフトウェア」で何が「個人情報」かの線引きを
  書いてあります。フォークして自分の環境で使う場合は必ず読んでください。

## 既知の弱点

公開にあたって隠さず書きます。どれも実害は小さいものです。

- ユーザーのストレージ配下に、**中身が空のサービスフォルダと `.lock` が残る**ことが
  あります。ロックを取るためにフォルダを先に作る作りで、存在しないキーを削除した
  だけでも発生します。アカウント削除時には丸ごと消えるので蓄積はしません。
- フォロー相手が退会しても、フォローしている側の配列からIDが消えません。一覧表示では
  解決できないものを黙って落とすため、**「フォロー中 3」と出て2件しか並ばない**ことが
  あります。
- 自前でデータを持つサービス側の孤児(退会した人のチャットルーム等)は、本体からは
  掃除しません。各サービスが `account_exists` で自分で確認する設計です。
